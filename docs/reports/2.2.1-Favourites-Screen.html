Overview

User story 2.2.1 — Favourites Screen has been opened on branch feature/2.2.1-favourites-screen.

Refinement Summary

The story was comprehensively refined with the following outcomes:

Functionality & Scope

  • Favourites screen displays products from the local Room database (local-only, no network calls)
  • Users can remove products from favourites with a swipe action or button
  • Navigation from bottom navigation bar links to the Favourites tab
  • Empty state shows enriched messaging when no favourites are saved
  • Loading and error states are handled gracefully

Acceptance Criteria

Categorised into: Display, Remove behaviour, Navigation, Empty state, Loading state, Error state, Analytics, and Consistency.

Implementation Delta

  • Add TrackScreenViewed intent to track screen view with favourite_count parameter
  • Enrich empty-state message with actionable guidance
  • Analytics event: favourites_screen_viewed emits only anonymous favourite_count integer (no PII)

Data Model

No new domain entities required. Reuses existing Product model and FavouritesRepository queries. Existing FavouriteEntity in Room database is the storage layer.

Files to Modify

7 files across the :app module:

  • Intent files (1 new intent class)
  • State & Effect files (new state and effect classes)
  • ViewModel implementation
  • Screen composable
  • Navigation routing
  • Unit and Compose UI tests

Test Coverage

  • Unit tests: 5 new scenarios covering load, remove, tracking, empty, and error states
  • Compose UI tests: 3 new scenarios covering display, remove button interactions, and empty state

Risk Assessment

  • Security: Low risk — analytics event contains only anonymous favourite_count integer, no PII
  • Performance: Medium concern — fetching full product list for subset acceptable at current scale (~20 products)
  • GDPR: No obligations — no PII stored or transmitted

Definition of Done

Comprehensive DoD checklist defined including unit tests passing, Compose UI tests passing, code coverage at 95%+, detekt passing, branch review and approval, and manual on-device verification.
