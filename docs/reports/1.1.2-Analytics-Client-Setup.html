Questions Asked and Answers

  1. No-op class? → No separate no-op. Empty registry = silent no-op.
  2. Logcat testing strategy? → Both: extract pure formatter function + mockkStatic(Log::class)
  3. Thread safety? → CopyOnWriteArrayList (read-heavy/write-rare pattern)
  4. Default debug provider registration? → Deferred to caller (story 1.1.3 DI wiring)
  5. Package name? → com.guidovezzoni.fakestore.core.analytics (parallel to core.network)

Key Design Decisions

  • AnalyticsProvider is an interface (not abstract class) for maximum SDK adapter flexibility
  • AnalyticsClient is a plain class with CopyOnWriteArrayList registry
  • No NoOpAnalyticsProvider — empty registry is the no-op path
  • Debug provider extracts pure formatter for testability
  • mockkStatic(Log::class) verifies Logcat integration without Robolectric
