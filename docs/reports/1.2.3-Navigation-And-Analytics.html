The user story was opened for development with branch feature/1.2.3-navigation-and-analytics created from main.

Navigation Structure

Implemented bottom navigation bar with 3 tabs:

  • Products — Main product list screen
  • Favourites — Bookmarked products
  • Profile — User profile screen

Navigation state is preserved across tab switches and screen rotation.

Analytics Integration

Product list analytics event product_list_viewed is logged once per screen visit on the Content state only, ensuring accurate tracking without duplicate events.

  • 12 navigation-related criteria (tab switching, state preservation, deep linking)

Unit Test Strategy

ViewModel analytics testing includes 4 test cases:

Risk Assessment

Category Level Notes
Security LOW No PII transmitted; analytics provider is debug-only at this stage
Performance MEDIUM State preservation requires careful deduplication logic to avoid memory leaks; SavedStateHandle lifecycle must be managed correctly
GDPR/Consent MEDIUM Consent mechanism required before production analytics provider is integrated; current debug-only implementation does not require user consent

Key Assumptions

  1. Bottom navigation remains visible across all three screens (not hidden on scroll)
  2. Deep linking to tabs is out of scope for this story; handled in a follow-up
  3. Favourites and Profile screens have placeholder content; full implementation is separate work
  4. Analytics provider integration (Firebase, Mixpanel, etc.) is deferred; currently uses debug AnalyticsProvider
  5. State restoration after process kill is deferred; navigation state is lost on app restart

Exploration Findings

Codebase exploration confirmed the following architecture:

  • MVI pattern with stateful/stateless composable overloads, ProductListViewModel taking only GetProductsUseCase
  • AnalyticsClient in :core is a thread-safe dispatcher; AnalyticsModule provides it as a Hilt @Singleton
  • MainActivity calls ProductListScreen directly — no Scaffold, no navigation
  • No androidx.navigation:navigation-compose dependency exists in the project
  • hilt-navigation-compose and material-icons-extended already present

Key Design Decisions

  • AppDestination as a sealed interface with @Serializable data object routes (type-safe navigation-compose 2.9.8)
  • MainUiState.selectedDestination is ViewModel-owned state, not derived from NavController
  • Tab taps flow: MainUiIntent.TabTapped → ViewModel logs analytics + emits MainUiEffect.NavigateToTab → MainScreen calls navController.navigate()
  • product_list_viewed logged inline in ProductListViewModel.loadProducts()'s onSuccess branch — no new intent needed
  • BottomNavigationBar is fully stateless: (selectedDestination, onTabTapped, modifier) — independently testable via Compose UI tests
