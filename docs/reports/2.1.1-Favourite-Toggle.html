2.1.1 — Favourite Toggle & Persistence

Story: 2.1.1 Branch: feature/2.1.1-favourite-toggle Created: 2026-08-11

Opening

11 Aug 2026

Source: sdlc:sdlc_open_story

User story 2.1.1 opened for development on branch feature/2.1.1-favourite-toggle. The story introduces the ability to favourite and unfavourite products with local persistence.

Refinement Highlights

  • Acceptance criteria expanded into logical groups: icon display, toggle behaviour, persistence, Favourites screen integration, analytics tracking, domain layer contracts, and strings/i18n
  • Error handling criteria defined: UI reverts to previous state on database failure with snackbar notification
  • Room database model specified: single productId column as primary key, supporting full delete + re-add for toggle semantics
  • Confirmed no API changes required — favourites are local-only and do not interact with the Fake Store API
  • Complete file modification matrix identified across :data, :domain, :app, and :core modules
  • Key technical concerns documented:
    • Room is new to the project; migration strategy and module dependencies require careful planning
    • Favourites screen needs access to the cached product list (likely via an in-memory or database-backed cache)
    • Toggle icon requires semantic accessibility labelling (e.g. content description reflecting "favourite" state)
  • Privacy and data governance: no GDPR concerns — only integer product IDs are stored, no PII
  • Definition of Done established with 20-item checklist covering implementation, testing, code quality, and documentation

Change Proposal

11 Aug 2026

Source: sdlc:sdlc_propose_change

Exploration Findings

  • MVI pattern consistently applied across ProductListViewModel and MainViewModel; new code follows established UiState/UiIntent/UiEffect conventions
  • Room is entirely new to the project — no existing database, no Room entries in libs.versions.toml, no KSP plugin on :data
  • FavouritesScreen is a bare placeholder Text with no ViewModel or MVI scaffolding — full buildout required
  • ProductListUiEffect is an empty sealed interface — first real one-shot effect usage in the project
  • combine() pattern (merging a one-shot product fetch with a reactive Room flow) is new to this codebase
  • Analytics API (AnalyticsClient.logEvent()) is already integrated in ProductListViewModel — same pattern reused
  • Existing strings in values/ (English) and values-es/ (Spanish) — both require new entries
