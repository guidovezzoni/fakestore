# Get Products Use Case

**Epic**: 1 — Product Catalogue
**Feature**: 1.1 — Data Layer & Analytics Setup
**Modules created**: `:core`, `:domain`, `:data`

## User Story

As a developer, I want a `GetProductsUseCase` backed by a Retrofit service that exposes `Flow<Result<List<Product>>>` so that the UI can react to loading, success, and error states.

## Acceptance Criteria

- [ ] `:core` module provides a configured Retrofit instance (base URL `https://fakestoreapi.com`)
- [ ] `:data` defines an `ApiService` with `suspend fun getProducts(): List<ProductDto>`
- [ ] `Product` domain model lives in `:domain` with no Android or Retrofit imports
- [ ] `ProductRepository` interface is defined in `:domain`; implementation lives in `:data`
- [ ] `GetProductsUseCase` in `:domain` returns `Flow<Result<List<Product>>>`
- [ ] Network errors are caught and surfaced as `Result.Failure` (no unhandled exceptions reach the ViewModel)

## Technical Notes

- Architecture: Clean Architecture — `:app` depends on `:domain`; `:data` implements `:domain` interfaces
- The API returns a plain array of 20 products; no pagination metadata is available — load all items in a single call
- The repository should be typed to be pagination-ready (e.g. wrap response in a `Page<T>`) even if the current call returns everything at once
