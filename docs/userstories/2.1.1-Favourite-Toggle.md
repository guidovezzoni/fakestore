# Favourite Toggle & Persistence

**Epic**: 2 — Favourites Management
**Feature**: 2.1 — Favourite Toggle & Persistence
**Modules**: `:app`, `:domain`, `:data`, `:core`

## User Story

As a user, I want to tap a toggle icon on a product card to add or remove it from favourites so that the action is immediate, visible, and persisted across app restarts.

As a product owner, I want `favourite_added` and `favourite_removed` analytics events (with product ID) logged on each toggle so that favouriting behaviour is measurable.

## Acceptance Criteria

- [ ] Each product card shows a filled icon when the product is a favourite, and an outline icon when it is not
- [ ] Tapping the icon toggles the state immediately (optimistic update in the UI)
- [ ] The icon state is consistent between the Products screen and the Favourites screen
- [ ] Toggle is handled by `ToggleFavouriteUseCase` in `:domain`
- [ ] Favourite product IDs are stored in a Room `FavouriteEntity` table in `:data`
- [ ] On app restart, the persisted IDs are read and the favourite icons reflect the saved state
- [ ] Removing a favourite deletes the corresponding row from the database
- [ ] `favourite_added` is logged with param `product_id` when a product is added to favourites
- [ ] `favourite_removed` is logged with param `product_id` when a product is removed from favourites
- [ ] No event is logged if the toggle operation fails (e.g. database error)

## Technical Notes

- MVI intent: `ToggleFavourite(productId: Int)`
- Favourite state is derived by combining the product list flow with the favourites ID flow in the ViewModel
- `FavouritesRepository` exposes `Flow<List<Int>>` — Room emits updates reactively, no manual refresh needed
- Room database is a singleton provided via Hilt
- Analytics call is made inside `ToggleFavouriteUseCase` or the ViewModel after a successful DB write, not in the composable
