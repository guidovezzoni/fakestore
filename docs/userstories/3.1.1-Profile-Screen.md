# Profile Screen

**Epic**: 3 — User Profile
**Feature**: 3.1 — Profile Screen
**Modules**: `:app`, `:core`, `:domain`, `:data`

## User Story

As a user, I want a Profile screen that displays my name, email, and live favourite count — with loading and error states — so that I can see my account information at a glance.

As a product owner, I want a `profile_screen_viewed` analytics event logged when the Profile screen loads.

## Acceptance Criteria

### User Profile Data
- [ ] `GET https://fakestoreapi.com/users/8` is called and the response maps to a `UserProfile` domain model (name, email, username)
- [ ] Name and email are displayed on the Profile screen
- [ ] `GetUserProfileUseCase` in `:domain` exposes `Flow<Result<UserProfile>>`

### Favourite Count
- [ ] The number of favourited products is shown on the Profile screen
- [ ] The count updates reactively — no manual refresh required after toggling a product on another screen
- [ ] The count is derived from `GetFavouritesUseCase`, not from a separate API call

### Loading & Error States
- [ ] A loading indicator is shown while the user profile is being fetched
- [ ] An error message with a "Retry" button is shown if the API call fails
- [ ] The favourite count continues to update reactively even while a profile reload is in flight
- [ ] Loading/error composables are shared from `:ui` (same components used on the Products screen)

### Analytics
- [ ] `profile_screen_viewed` is logged once each time the Profile screen enters composition
- [ ] The event is logged regardless of whether the profile data has loaded yet

## Technical Notes

- `UserRepository` interface in `:domain`; implementation in `:data`
- Reuses the same Retrofit instance from `:core`
- The Profile ViewModel combines `GetUserProfileUseCase` and `GetFavouritesUseCase` flows using `combine()`
- MVI state: `Loading`, `Content(profile, favouriteCount)`, `Error`
- Only the profile fetch determines the loading/error state; the favourite count is always live
- Same analytics pattern as `product_list_viewed`: `LaunchedEffect(Unit)` triggers a ViewModel intent
